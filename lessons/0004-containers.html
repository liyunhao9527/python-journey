把多次学习存成记录。

1. 从一段摘要到多条记录

上一课能把一次学习输出成文字。现在要保存两次学习的主题与分钟数，稍后还能修正其中一条。后面的支出分析也需要先把“一笔支出”和“多笔支出”组织成数据。

先不运行，写下两个输出。解释 strip 是否修改原字符串，以及为什么这里需要 int；不确定时回看第三课。

raw = "  容器  "
topic = raw.strip()
print(raw == topic)
print(int("25") + 5)
写完预测再核对

输出 False 和 30。strip 返回清理后的字符串，raw 仍带空格；int 把文本转成整数后才能与整数 5 相加。

2. 列表装记录，字典装字段

容器是把多个对象组织在一起的对象。本课先用两种：列表 list 按位置保存元素，可以追加、替换或删除；字典 dict 保存“键 → 值”，用名字查找一项数据。键相当于字段名，例如 topic 对应主题，minutes 对应分钟数。

列表写成 [元素, 元素]，位置从 0 开始。字典写成 {"键": 值}，本课的键都是字符串，需要引号。records[0]["minutes"] 先取列表中的第一条字典，再取它的 minutes 值。这种容器里还有容器的结构称为嵌套。

append(x) 把一个元素追加到列表末尾；len(records) 取得记录数。record.get("note", "未填写") 在键不存在时返回默认值，便于读取可选备注。它不会把默认值写入字典。

first = {"topic": "字符串", "minutes": 25}
second = {"topic": "容器", "minutes": 30}
records = [first]
records.append(second)
records[0]["minutes"] = 35

total = records[0]["minutes"] + records[1]["minutes"]
print(f"共 {len(records)} 条记录，合计 {total} 分钟。")
print(records[1]["topic"])
print(records[0].get("note", "未填写"))

代码已保存在 demos/04-containers/main.py。先预测三行输出，再从项目根目录运行：

uv run python demos/04-containers/main.py
核对运行结果
共 2 条记录，合计 65 分钟。
容器
未填写

第一条从 25 改为 35，再与第二条的 30 相加。first 与 records[0] 指向同一个字典，因此 first["minutes"] 也变为 35。

同一任务的 TypeScript 写法

这里用普通对象保存已知字段，用 Array 保存记录。! 是 TS 的非空断言：让类型检查器相信该位置存在，运行时不增加检查。本例由数组构造和 push 保证两项存在；不能把断言当作输入校验。

const first: { topic: string; minutes: number; note?: string } = {
  topic: "字符串", minutes: 25,
};
const second = { topic: "容器", minutes: 30 };
const records = [first];
records.push(second);
records[0]!.minutes = 35;

const total = records[0]!.minutes + records[1]!.minutes;
console.log(`共 ${records.length} 条记录，合计 ${total} 分钟。`);
console.log(records[1]!.topic);
console.log(Object.hasOwn(records[0]!, "note") ? records[0]!.note : "未填写");

note? 声明可选备注；Object.hasOwn 检查自有字段是否存在，存在则读取，否则返回默认文字。文件为 demos/04-containers/equivalent.ts。支持原生类型擦除的 Node 可运行 node demos/04-containers/equivalent.ts，或使用现有 TS 工具链；本例还需支持 Object.hasOwn 的运行时（Node 16.9+）。Node 擦除类型后执行，不替代 tsc 检查。

目标差异与类比边界优势、代价与适用场景
追加记录append 与 push 都修改原容器。append 返回 None，push 返回新长度。本例无需返回值，两者无明显优劣。Python 不要写 records = records.append(second)，否则名字会绑定到 None。
按位置读取Python 越界报 IndexError；JS 数组越界通常得到 undefined。TS 的 noUncheckedIndexedAccess 可把可能的 undefined 加进索引结果类型；在 strictNullChecks 下需处理它。Python 越界当场报错；TS 可在运行前提醒，但依赖配置，JS 运行时仍要处理缺失。
按字段读取dict 用 ["topic"]，不能用 .topic。缺失键用 [] 读取会报 KeyError；get 可给默认值。JS 缺失属性通常为 undefined，TS 对已知对象访问未声明字段会报类型错误。固定字段可借 TS 推断提前发现拼写错误；Python 字典便于动态增减字段，需在运行时确认键。get 适合可选项，必填字段用 [] 更容易暴露遗漏。
添加或更新字段Python record["note"] = "复习" 可新增字段，同一个键再次赋值会覆盖旧值。TS 本例先声明 note? 才能在该类型上添加备注；只从 topic、minutes 推断出的类型不含 note。字典适合字段随数据变化的记录；TS 明确结构利于维护，需额外类型声明。dict 也能做映射，但不等同于所有 JS 对象或 Map 行为。

试着把第二条分钟数改为 0，再运行。还可以用 "note" in first 判断键是否存在：字典的 in 查键，不查值。get 只在缺键时使用默认值；如果 note 已存在且值为 None，就返回 None。

Python 3.7 起 dict 保证插入顺序，但键仍是查找依据，first[0] 查的是整数键 0，不是第一个字段。规则见官方字典教程。

3. 复制了哪一层？

第二课讲过赋值会共享对象。现在需要一个临时列表，用来试着修改记录；只写 draft = records 会让两个名字指向同一个列表。

浅复制只创建外层容器，内部元素仍指向原来的对象。records.copy() 创建新列表，里面的字典没有被复制。适合独立增删列表元素；若要独立修改某条记录，还要复制那条字典。

records = [{"topic": "容器", "minutes": 30}]
draft = records.copy()
draft.append({"topic": "函数", "minutes": 20})
draft[0]["minutes"] = 40
print(len(records), len(draft))
print(records[0]["minutes"])
const records = [{ topic: "容器", minutes: 30 }];
const draft = [...records];
draft.push({ topic: "函数", minutes: 20 });
draft[0]!.minutes = 40;
console.log(records.length, draft.length);
console.log(records[0]!.minutes);
  • 共同点：两段都先输出 1 2，再输出 40。新列表或数组可独立追加，第一条记录仍共享。
  • 边界：copy 与数组展开都不递归复制内层对象。Python 列表切片 records[:] 也是浅复制。
  • 取舍：两种写法在这里无明显优劣。浅复制能保留内部共享，适合只改外层的任务；修改内层前，要明确哪些对象需要独立。
操作原列表临时列表
copy 后1 个元素 → 字典 A1 个元素 → 同一个字典 A
append 后仍为 1 个元素2 个元素 → A 和新增的 B
修改 draft[0] 的字段后A 的 minutes 为 40A 的 minutes 为 40

要单独编辑第一条，在赋值修改字段之前写 draft[0] = draft[0].copy()；对应本例 TS 对象可写 draft[0] = { ...draft[0]! }。两者都只复制这一层记录，适合本课字符串和整数值；如果字段里还有列表，那个列表仍共享。

4. 固定搭配与去重

元组：固定位置上的搭配

元组 tuple 是不能增删元素、不能替换元素位置的序列。例如一对“主题、分钟数”在创建后不需要调整结构，可以写成元组。索引与列表一样从 0 开始；逗号组成元组，单元素要写 ("容器",)，("容器") 仍是字符串。

session = ("容器", 30)
print(session[0])
# session[1] = 40  # 取消注释会报 TypeError
const session: readonly [string, number] = ["容器", 30];
console.log(session[0]);
// session[1] = 40; // 取消注释会被 TS 类型检查拒绝
  • 两段都读取固定位置并输出“容器”；本例 TS readonly 元组还能声明各位置的类型。
  • 不可变的边界不同：Python 在运行时禁止替换 tuple 的元素；TS readonly 只约束静态检查，类型擦除后仍是普通 JS 数组，不会自动冻结。
  • 取舍：元组适合位置含义明确的短组合，字段多时字典名字更易读。TS 的类型提示便于查错，运行时限制需另做处理；Python tuple 的限制直接生效，但不会自动检查每个位置的业务类型。

元组也可能包含可变对象。session = ("容器", [30]) 后执行 session[1].append(10) 是允许的：内层列表改变，元组仍指向原来的列表。不可变不等于内部所有对象都不可变。

集合：只关心有哪些不同主题

集合 set 保存不重复的元素，不保证元素顺序。当同一主题学了多次，可以把主题列表交给 set 去重，再用 len 统计不同主题数。in 检查某个主题是否存在。

topics = ["容器", "字符串", "容器"]
unique_topics = set(topics)
print(len(unique_topics))
print("容器" in unique_topics)
const topics = ["容器", "字符串", "容器"];
const uniqueTopics = new Set(topics);
console.log(uniqueTopics.size);
console.log(uniqueTopics.has("容器"));
  • 两段都得到 2 与真值（Python 显示 True，JS 显示 true），字符串主题去重可以类比。
  • 顺序边界：Python set 不保证迭代顺序，JS Set 保留插入顺序。Python set 不能用 [0] 读取第一个元素。
  • 元素边界：Python set 的元素、dict 的键必须可哈希，即能提供稳定的哈希值并满足相等性规则，供容器查找。字符串、整数可用；list、dict 不可用。JS Set 可直接放对象，按对象身份区分，不按字段内容去重。
  • 取舍：本课统计主题数，两者无明显优劣。Python set 适合去重与成员判断；要保留学习顺序，应继续保存原列表。JS Set 的插入顺序可直接用于按首次出现顺序展示。

空集合写 set()，{} 是空字典。现在只对字符串主题去重；不要直接写 set(records)，记录字典不可哈希。规则见Python 集合教程与 JS Set。
