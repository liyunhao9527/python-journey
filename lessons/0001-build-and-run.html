1. 今天只做一件事

让你写的 .py 文件在自己的电脑上运行，并确认到底是哪一个 Python 在执行它。本课会借助你熟悉的 TypeScript / Node.js 说明差异。

Python 文件可以直接交给解释器执行。常见的 CPython 实现会先把源码编译为字节码，再执行；“不需要手动编译”不等于“内部没有编译过程”。导入模块时可能生成 __pycache__，它不是你要双击运行的独立程序。

像你用 Node.js 运行 JavaScript 一样，Python 脚本也由对应的运行环境执行。本课不生成独立的原生可执行文件；换一台机器时，通常仍需要 Python 和相应依赖。TypeScript 的类型检查与 Python 的解释执行不是同一个步骤。

2. 用 uv 安装 Python

uv 可以安装多个 Python 版本，也能管理项目环境和依赖。你可以把它的版本管理能力类比为 fnm；接下来还会用它完成类似包管理器的工作。

先从 uv 官方安装指南选择适合自己电脑的安装方式。安装完成后，打开终端执行： 

uv --version
uv python install 3.14

第一条确认 uv 可用，第二条安装 Python 3.14。uv 会选择适合当前电脑的发行包；不需要先手动安装 Python。再次执行时，如果已有满足请求的 uv 管理版本，就会复用。

如果希望自行下载安装包，也可以访问 Python 官网下载页，选择适合自己电脑的版本安装。两种安装方式任选其一即可，本课接下来的项目管理统一使用 uv。

这些命令输入在终端中，不是浏览器或 Python 的 >>> 提示符中。

3. 虚拟环境与项目版本

什么是 Python 虚拟环境？

虚拟环境是为一个项目单独建立的 Python 运行环境。 它有自己的 Python 解释器入口和第三方包安装目录，基于某个已安装的 Python 创建。本项目用 .venv 这个目录保存它。

为什么要单独建立？假设项目 A 需要 Django 4，项目 B 需要 Django 5。 如果都把依赖装进同一个环境，为 B 升级 Django 时就可能影响 A。 分别使用虚拟环境后，每个项目都可以保留自己需要的依赖版本。 这里的 Django 只是举例，本课不需要安装它。 

project-a/
└── .venv/    # 项目 A 的环境，安装 Django 4

project-b/
└── .venv/    # 项目 B 的环境，安装 Django 5

对照你熟悉的 Node.js，node_modules 也保存项目依赖；Python 的虚拟环境除了单独的依赖目录，还提供对应的 Python 解释器入口。 两个环境可以基于同一个 Python 版本，也可以分别基于不同版本： 选择 Python 版本和隔离项目依赖，是两个相关但不同的问题。

“虚拟”不表示运行了一台虚拟机。虚拟环境主要隔离 Python 依赖， 不会隔离文件或网络访问；程序仍然在你的电脑上运行。

uv 怎样管理这个环境？

前面的 uv python install 准备 Python 解释器。 接下来用 uv python pin 记录本项目选择的版本， 用 uv sync 创建或同步项目的 .venv， 最后用 uv run 在这个环境中运行代码。 因此，不需要为每个项目都去官网重新下载安装包。

固定版本，再创建项目环境

在终端中进入 python-journey 项目根目录，也就是能看到 pyproject.toml 的目录，然后依次执行： 

uv python pin 3.14
uv sync
uv run python --version
uv run python -c "import sys; print(sys.executable)"

uv python pin 3.14 把版本要求写入 .python-version。这里固定的是 3.14 系列；若需要精确到补丁版本，也可以指定完整版本号。本仓库已经包含这个文件，再执行一次可以确认自己的操作。

uv sync 根据项目配置和锁文件创建或同步 .venv，把本项目的解释器入口和依赖放在独立环境中。本课只用标准库，不需要额外安装第三方包。

uv run 在项目环境里执行后面的命令，并在需要时同步环境。版本检查应显示 Python 3.14.x；路径检查应指向当前项目的 .venv。

文件 / 目录 负责什么
.python-version 本项目选用的 Python 版本，目前是 3.14。
pyproject.toml 项目元数据、依赖和兼容的 Python 范围；兼容范围不等于本次运行版本。
uv.lock 记录依赖解析结果，便于在其他电脑重建环境。
.venv/ 本机的项目虚拟环境，不提交到 Git；换电脑后用 uv sync 重建。

进入目录，就会自动切换吗？

单纯 cd 到项目不会让 uv 自动改变终端中的 python 命令。与 fnm 的目录切换钩子不同，uv 常用的方式是在执行 uv run 时选择项目环境。因此后面的练习统一使用 uv run python ...，不需要手动激活虚拟环境。

已经从 Python 官网安装过了，还能用 uv 吗？

可以。uv 能发现已安装且满足项目版本要求的 Python，并用它创建项目环境；默认配置下，缺少合适的解释器时也可以自动下载。无论解释器最初怎样安装，都用 uv run python --version 和路径检查来确认当前项目实际使用的是哪一个。

4. 写下第一段代码

打开仓库里的 demos/01-hello/main.py。内容如下；也可以先在自己的空文件里手动敲一遍。 

name = "Python"
minutes = 25

print(f"你好，{name}！")
print(f"今天专注学习 {minutes} 分钟。")

name 和 minutes 是变量名，分别绑定到字符串和整数。print() 输出文字。字符串前的 f 让花括号中的表达式先求值，再放入文本；语句末尾不需要分号。 

uv run python demos/01-hello/main.py

在仓库根目录执行后，应该看到：

你好，Python！
今天专注学习 25 分钟。

脚本里的顶层语句从上到下执行。本例不需要先定义 main()。以后把代码拆成可导入模块时，我们再引入 if __name__ == "__main__":，避免导入模块时意外执行入口逻辑。

用熟悉的 TypeScript 对照

下面的 TS 程序与上面的 Python 程序输出完全相同。文件已保存在 demos/01-hello/equivalent.ts。 

function main(): void {
  const name: string = "Python";
  const minutes: number = 25;

  console.log(`你好，${name}！`);
  console.log(`今天专注学习 ${minutes} 分钟。`);
}

main();

TS 用 const 声明绑定，用反引号和 ${...} 插值；Python 直接赋值，用 f"...{...}" 插值。这里的 main 只是普通函数名，TS 必须显式调用它。前面的 Python 示例在顶层直接执行，不需要这个包装。

运行 TypeScript 对照 
node --version
node demos/01-hello/equivalent.ts

上面的命令要求 Node 支持原生 TypeScript 类型擦除，本机 Node 25 已验证。若现有 Node 不支持，可沿用你已有的 TS 编译或执行工具；Python 主线不依赖 Node。Node 擦除这些类型注解后执行，不会替代 tsc 做类型检查。

6. 遇到报错，先看最后一行

Python 的错误信息通常在最后一行写出异常类型和说明，再向上找文件名、行号和调用位置。不要一次改很多地方：先找到一处原因，修改后重新运行。

现象 原因与下一步
找不到 uv 命令 按 uv 官方指南完成安装，重新打开终端，再执行 uv --version。
can't open file 确认当前目录能看到 pyproject.toml，再检查文件相对路径和是否已经保存。
NameError 变量名拼错，或在赋值前使用了它。名称区分大小写。
SyntaxError 检查引号、括号和标点；代码使用英文标点。
IndentationError 顶层语句不要随意缩进；代码块统一用四个空格。

如果终端显示 >>>，说明进入了 Python 交互环境。输入 exit() 返回终端，再执行文件运行命令。

7. 独立完成一个学习计时账单

在 demos/01-hello/ 新建 practice.py，定义变量 days = 5 和 minutes_per_day = 25，输出“一共学习 125 分钟。”。再把天数改为 7，确认结果变成 175。乘法使用 *。

先从空文件写，再打开下面的答案。执行时把第一课的运行命令最后一个文件名改为 practice.py。

参考实现与运行命令 
days = 5
minutes_per_day = 25
total_minutes = days * minutes_per_day

print(f"一共学习 {total_minutes} 分钟。")
uv run python demos/01-hello/solution.py

仓库的 solution.py 是参考答案。修改你自己的 practice.py，依次用 5、7、0 天验证结果为 125、175、0；不要只把正确输出直接写死到 print 中。

完成后留下这些证据

  • 通过 uv run 得到的解释器路径和 Python 版本。
  • 用自己的话解释虚拟环境是什么，以及为什么两个项目可以安装同一个包的不同版本。
  • 自己写的 practice.py，以及 5、7、0 天的输出。
  • 用自己的话说明 uv python pin、uv sync 和 uv run 的区别。
  • 一个仍然不确定的问题，或你修复过的一条错误。

这些是第一课的过关标准。打开页面和展开答案都不代表已经掌握。
